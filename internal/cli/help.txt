dashy - minimal AI coding agent (TUI and ACP editor integration)

USAGE
  dashy [--config FILE|-c FILE] [--no-global] [--resume ID]
  dashy acp [--config FILE] [--no-global]
  dashy models [--provider NAME]
  dashy tasks run [-s ID] COMMAND...
  dashy tasks list|status|stop [-s ID] [TASK]
  dashy view [-s ID] PATH...
  dashy read [-o LINE] [-n COUNT] FILE
  dashy grep [-i] [-l] [-g GLOB] PATTERN [PATH...]
  dashy grep --files [-g GLOB] [PATH...]
  dashy write FILE < CONTENT
  dashy patch FILE < BLOCKS
  dashy version
  dashy --help | -h | help

FLAGS & COMMANDS
  --config, -c    Project instructions instead of ./DASHY.md (-c is TUI only).
  --no-global     Skip $DASHY_HOME/DASHY.md. Both TUI and ACP load it by default.
  --resume ID     Resume a saved project session in the TUI.
  --provider NAME Restrict the models listing to one provider.
  -s ID           Target a running session for tasks/view; defaults to DASHY_ENDPOINT.
  --help, -h      Show this help reference.
  acp             Local ACP v1 preview over newline-delimited JSON-RPC on stdin/stdout.
                  Configure provider/model in the TUI first. Text and PNG/JPEG prompts. Commands,
                  instruction blocks and task helpers run freely, exactly as in the TUI.
                  No permission prompts or sandbox. Use only trusted projects; see docs/ACP.md.
  models          Print PROVIDER<TAB>MODEL for configured providers. Errors go to stderr.
  tasks run       Start a background command in a running TUI session. Output goes to a
                  private log. The session receives a <task-result> when it ends.
  tasks list      List background tasks of the target session.
  tasks status    Show one task's state and output log.
  tasks stop      Stop a running task and its process group.
  view            Queue PNG/JPEG images in the target session without blocking its turn.
  read            Numbered text lines, -n COUNT (default 2000), starting at -o LINE.
  grep            Go regexp search; -i ignores case, -l lists matching file names,
                  -g filters names by glob. --files lists files (at most 500).
                  Git projects include tracked and unignored hidden files; the fallback
                  skips hidden entries and node_modules. At most 200 matches; no match exits 1.
  write           Atomically replace/create FILE with stdin; preserve existing permissions.
  patch           Apply blocks from stdin, each search occurring exactly once:
                  <<<<<<< SEARCH
                  old text
                  =======
                  replacement text
                  >>>>>>> REPLACE
                  Invalid/ambiguous blocks leave the file unchanged.
  version         Print the version.

INSTRUCTIONS & SETTINGS
  Instructions load from $DASHY_HOME/DASHY.md and ./DASHY.md (or --config FILE).
  The assembled prompt is stored in session history. /resume reuses it;
  /reload assembles and stores a new snapshot. Instructions are never user input.
  Settings live in $DASHY_HOME/dashy.db. TUI commands /connect, /models and /settings
  configure providers, model, reasoning, display, and shell_output (default 8192 bytes).
  Changes apply before the next model request; sessions keep their own model selection.

DASHY BLOCKS
  Fenced blocks with info string 'dashy' run with bash -c in the session directory.
  Timeout: 30 seconds; stdout: 64 KiB. Review blocks in untrusted projects first.
  Blocks execute automatically in both the TUI and ACP.
  API keys are not exported as settings, but subprocesses inherit the user's environment.
  Shell execution has the user's permissions and network access; it is not a sandbox.

ENVIRONMENT VARIABLES
  DASHY_HOME        State directory (default ~/.dashy), including dashy.db, locks/,
                    run/ sockets, attachments/, and private tasks/ output logs.
  DASHY_SESSION_ID  Active session ID, exported to the bash tool and instruction blocks.
  DASHY_ENDPOINT    This session's Unix socket for tasks/view; never inherited from a parent.
  DASHY_MODE        Instruction block mode: 'tui' or 'acp'.
  DASHY_SOURCE      Instruction assembly source: 'startup', 'new', 'resume', or 'reload'.

TERMINAL STATUS
  The TUI emits OSC 7501 reports. ACP emits only protocol frames on stdout;
  diagnostics and process failures go to stderr.
